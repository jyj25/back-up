# 03 · 요구 명세·수용 기준 (A03)

우선순위: **필수** = 발표 시연에 꼭 필요 / **선택** = 시간이 되면.

## 수용 기준

**REQ-01 분류** (AI 원본 A03 I-02·I-03·I-05 기준, 값은 가정)
- 종류: `can`, `pet`, `paper` + 빈 트레이 `empty` (ADR-05 결정). **판정 이름 = 로봇의 통 이름(`stations.json`)** — 대응표 없음.
- 확정: 1등 확신도 ≥ 0.80, 1·2등 차이 ≥ 0.20, `empty` 가 아니고, 같은 결과가 **3번 연속**이면 확정을 한 번 낸다.
- 확정 뒤에는 `empty` 가 3번 연속 나올 때까지 새 확정을 내지 않는다 (같은 물건 중복 방지).
- 출력은 IF-01 형식. 조건 미달은 "판정 없음"(`class: null`) — 로봇은 움직이지 않는다.
- 성능: 테스트 셋과 보드 실측 정확도 **90% 이상**, 추론 **1초 이내**. 미달이면 재학습(최소 1회) 후 06 에 FAIL 기록.
- 세부(수집기 C-, 영상 펌웨어 F-, 학습 스크립트 T-, 추론 I-)는 AI 원본 A03.

**REQ-02 통 찾아가기** (결정)
- 해당 통의 마커를 찾을 때까지 제자리 회전, 찾으면 가운데로 맞추며 다가간다.
- 도착: 마커가 화면 너비의 30% 이상, 또는 마커를 정면으로 보고 초음파 25cm 이하. 실제 목표는 **통 앞 20~30cm**.
- 한 바퀴 반(40걸음)을 돌아도 못 찾으면 `failed` 로 멈추고 이유를 보여 준다.
- 도착 후 뒤로 빠졌다가 출발점(마커 0)으로 돌아온다.

**REQ-03 안전** (결정)
- 모든 이동 명령은 지정 시간(최대 3초) 뒤 자동 정지한다. 연결이 끊겨도 선다.
- 속도는 상한(기본 150/255)을 넘지 않는다.
- 앞쪽으로 갈 때 초음파 15cm 이내에 물체가 있으면 멈추고 앞 이동을 거절한다.
- 수동 조종·정지 버튼이 오면 진행 중인 임무를 즉시 취소하고 멈춘다.
- 임무 중에 들어온 새 판정은 무시한다.

**REQ-04 수동 조종·수동 분류** (결정)
- 버튼을 누르는 동안만 움직인다 (앞뒤·회전·옆·대각선), 손을 떼면 멈춘다.
- 카메라 실시간 영상, 거리·상태 표시.
- 통 버튼을 누르면 그 통으로 임무를 실행한다 → 자동 판정이 안 될 때 시연을 이어 가는 **수동 분류** 수단.

**REQ-05 통에 넣기** (미정 — ADR-04)
- 최소 기준: 도착하면 노란 LED + 소리 3번으로 알리고 사람이 넣는다.
- 방법을 정하면 수용 기준을 다시 쓴다.

**REQ-06 기록·대시보드** (제안 — 서민형과 합의 전)
- 처리할 때마다 시각·종류·확신도·결과(완료/실패/취소)를 남긴다.
- 대시보드: 로봇 상태, 지금 하는 일, 판정 결과·확신도, 통별 개수, 오늘 처리량, 탄소 절감량.
- 탄소 절감 계수는 **출처를 함께 표기**한다. 출처 없는 숫자는 쓰지 않는다.
- 값이 없으면 0 이 아니라 "—" 로, 로봇 연결이 끊기면 "연결 끊김" 으로 표시한다.
- 데이터는 로봇 API(IF-02, 기록은 IF-04 예정)로 받는다.

**REQ-07 발표장 연결** (결정, 실기 미확인)
- 휴대폰 핫스팟을 라즈베리파이에 미리 등록해 두면 자동 연결된다.
- 자동 실행을 켜면 부팅 후 조종 서버가 뜬다.
- 노트북에서 같은 핫스팟의 로봇 주소를 찾을 수 있다.

**REQ-08 가득 참 알림** (선택, ADR-06)
- 센서 없이 통별 개수가 설정값(예: 10개)에 도달하면 웹·앱에 알린다. 기준 개수는 팀이 정한다.

**REQ-09 사진 수집** (AI 원본 A03 C-01~07, 구현됨 — 담당자 기록)
- 보드 카메라를 USB(Web Serial)로 연결해 영상 확인·촬영·연속 촬영, 클래스별 ZIP 다운로드.
- 모든 클래스에 손이 나온 사진을 같은 비율로, 클래스당 50장 이상.
- **로봇 위에 달았을 때와 같은 카메라 방향·거리**로 찍는다 (REQ-01 정확도 조건).
