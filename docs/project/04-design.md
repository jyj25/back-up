# 04 · 화면·구조·인터페이스·결정 (A05~A08)

## 구조 (DES-01)

```
 물건 ─▶ 트레이 ◀── XIAO ESP32S3 카메라 (분류) ── USB (IF-01) ──▶ 라즈베리파이 5 · 조종 서버
                                                                    ├ 라즈봇 기본 USB 카메라: 통 마커 찾기
                                                                    ├ 초음파: 거리·장애물
                                                                    └ 메카넘 바퀴 4개 (I2C 0x2B)
                                   │ HTTP (IF-02) · 휴대폰 핫스팟
             휴대폰 조종 화면 (DES-03)        웹 대시보드 · 웹앱 (DES-04, 노트북에서 실행)
```

| 요소 | 책임 | 실행 장치 | 원본 |
| --- | --- | --- | --- |
| 분류 펌웨어 | 판정·확정·결과 전송 | XIAO ESP32S3 | `yujeong/` (예정) |
| 조종 서버 | 이동·안전·임무·카메라·API | 라즈베리파이 5 | `jeongmin/robot/server/` |
| 조종 화면 | 수동 조종·임무 버튼 | 휴대폰 브라우저 (로봇 서버가 제공) | `jeongmin/robot/server/static/` |
| 대시보드 | 상태·기록·통계 | 노트북 브라우저 | `minhyeong/` (예정) |

- **저장**: 처리 기록은 로봇 서버가 보관 (IF-04, 예정). 원격 DB 없음.
- **경계**: 인터넷 없이 핫스팟 안에서만 동작. 배포된(https) 사이트에서 로봇 접속은 브라우저가 막으므로 대시보드는 노트북 `http://localhost` 로 실행.

## 임무 상태 흐름 (DES-02)

```
idle ─(임무 시작)→ search ⇄ align ⇄ approach → arrived → dumping → backing → (출발점으로) search … → done
                     │ 40걸음 못 찾음 → failed        수동 조종·정지 → cancelled (즉시 정지)
```

- 한 걸음 = 조금 움직이기(0.25초) → 멈추기 → 화면 보고 다시 판단. 판단 규칙은 `navigator.decide()` 한곳에 있다.
- `dumping` 단계는 지금 신호(LED + 소리)만 낸다 (ADR-04).

## 화면 (DES-03 조종 화면 · 구현됨)

- 위: 카메라 영상, 거리·라인·상태(장애물 정지 포함).
- 가운데: 방향 버튼 9개 + 회전 2개, 누르는 동안만 이동. 키보드 W/S/A/D/Q/E, Space 정지.
- 아래: 통 찾아가기 버튼(통마다), "쏟기·복귀" 선택, 진행 단계·보이는 마커, 임무 취소.
- 색만으로 상태를 전하지 않고 글자로도 표시한다. 접근성 전체 점검은 미확인.

## 화면 (DES-04 대시보드 · 서민형, 미확인)

제안: 로봇 연결 상태 / 지금 하는 일 / 통별 개수 / 오늘 처리량 / 탄소 절감량(근거 표시) / 최근 기록 목록.

## 인터페이스 계약

**IF-01 ESP32 → 라즈베리파이 (제안, 합의 전)**
- USB 시리얼 115200, 한 줄 = 한 결과, 줄 끝 LF.
- 형식: `RESULT <label> <confidence>` 예) `RESULT recycle 0.93`
- `label` 은 REQ-01 의 4개 중 하나, `confidence` 는 0~1 소수.
- `RESULT` 로 시작하지 않는 줄(디버그 출력)은 로봇이 무시한다.
- 로봇 쪽 수신은 **미구현** (TASK-R4).

**IF-02 로봇 HTTP API (구현됨, 자세히는 `jeongmin/README.md`)**
- 이동: `POST /api/move {action, speed, duration_ms}`, `POST /api/stop`
- 상태: `GET /api/status` (mode, moving, blocked, mission …)
- 임무: `POST /api/mission {station, dump, return_home}` → 202, `GET /api/mission`, `POST /api/mission/cancel`
- 마커·통: `GET /api/markers`, `GET /api/stations`
- 카메라: `GET /api/camera.jpg`, `GET /api/stream`
- 브라우저에서 부를 때 웹 주소를 `CORS_ORIGINS` 에 등록.

**IF-03 통 목록 `jeongmin/robot/stations.json` (구현됨)**
- `home`=마커 0, `recycle`=1, `general`=2, `vinyl`=3. 마커는 DICT_4X4_50, 한 변 10cm, 통 앞면 카메라 높이(약 15cm).

**IF-04 처리 기록 API (예정)**
- `GET /api/history` → `[{time, label, station, result}]` + 통별 개수. 형식은 서민형과 합의 후 고정.

## 결정 기록 (ADR)

**ADR-01 통 찾기는 ArUco 마커 — 결정 (10/30, 팀장)**
- 대안: 시간으로 움직이기(바퀴 회전 센서가 없어 오차가 쌓임) / 바닥 라인 따라가기(테이프 설치 필요, 경로 고정) / 마커.
- 선택 이유: 학습 없이 번호·방향·크기를 알 수 있고, 카메라로 계속 보며 고치므로 오차가 쌓이지 않음.
- 포기: 마커가 가려지거나 조명이 나쁘면 못 찾음. 재검토 조건: 실제 인식 거리가 1m 미만이면 마커 크기·배치 변경.

**ADR-02 분류는 로봇 위 ESP32 + USB — 결정 (10/30, 팀장)**
- 대안: 출발점에 고정한 카메라 + Wi-Fi / C270 웹캠 + 라즈베리파이에서 분류 / 로봇 위 ESP32 + USB.
- 선택 이유: Wi-Fi 상태와 무관, 케이블 하나로 전원·데이터, 엣지 AI 를 보여 줄 수 있음.
- 포기: 화질·모델 크기가 작음. 대체: 정확도가 낮으면 C270 + 라즈베리파이 분류로 바꿈 (로봇 쪽은 결과만 받으므로 구조 유지).

**ADR-03 이동은 '움직이고-멈추고-보기' 반복 — 결정 (10/30, 팀장)**
- 이유: 움직이는 중 흔들린 화면 대신 멈춘 화면으로 판단, 끊겨도 자동 정지와 맞물림. 포기: 이동이 느림(시뮬레이션 1회 약 30초).

**ADR-04 통에 넣는 방법 — 미정**
- 후보는 팀에서 검토 중. 정해지기 전 기본: 도착 신호 후 사람이 넣기.
- 정해지면 REQ-05·TASK-R6·TC 를 함께 고친다.
