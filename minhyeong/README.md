# minhyeong — 웹 · 앱 담당 (서민형)

분리수거 로봇의 **대시보드**와 **휴대폰 웹앱**, 발표 웹 슬라이드 배포를 맡는다. 취미는 축구.
작업은 `minhyeong` 브랜치에서 하고 Pull Request 로 main 에 합친다.

```
minhyeong/
├── README.md         이 문서
└── dashboard/        대시보드 (설치·빌드 없음)
    ├── index.html    화면 배치 (휴대폰은 아래 탭, 넓은 화면은 왼쪽 메뉴)
    ├── ui.js         7개 기능 화면
    ├── robot.js      로봇 API 를 읽어 화면용 상태를 만듦 (+ 로봇 없이 도는 가짜 로봇)
    └── start-dashboard.bat  더블클릭 실행 (로봇 IP 입력 → 서버 켜고 브라우저 열기)
```

## 바로 시작 (처음 쓰는 사람용)

준비물: **Windows 노트북 + Python** (없으면 https://www.python.org 에서 설치, 설치 화면에서 "Add python.exe to PATH" 체크)

1. **받기**: https://github.com/jyj25/back-up/archive/refs/heads/minhyeong.zip 을 받아 압축을 푼다 (git 을 쓰면 `git clone -b minhyeong https://github.com/jyj25/back-up`).
2. **노트북을 로봇과 같은 휴대폰 핫스팟에 연결**한다.
3. `minhyeong/dashboard/start-dashboard.bat` 을 **더블클릭**한다.
4. "로봇 IP" 를 물으면 로봇 주소를 숫자만 넣고 엔터 (예: `192.168.0.23`). 모르면 그냥 엔터 → 가짜 로봇으로 연습하다가, 화면의 **제어 → 관리자 → 로봇 서버 연결** 칸에 IP 를 넣고 "연결" 을 눌러도 된다.
5. 브라우저가 자동으로 열린다. 오른쪽 위가 **"실제 로봇"** 이면 연결 성공. 끝낼 때는 검은 창을 닫는다.

| 이렇게 보이면 | 이렇게 한다 |
| --- | --- |
| 오른쪽 위 "로봇 연결 끊김" | 같은 핫스팟인지, 로봇 서버가 켜졌는지, 로봇 IP 가 맞는지 확인 (로봇 IP 는 팀장님 `python find_robot.py`) |
| 연결은 안 되는데 IP 는 맞음 | 로봇 서버 `CORS_ORIGINS` 에 `http://localhost:8765` 가 있는지 팀장님께 확인. **포트 8765 를 바꾸지 않는다** |
| 검은 창에 "Python 이 없습니다" | Python 설치 (위 준비물) |
| 화면 글자·아이콘 모양이 깨짐 | 글꼴·아이콘을 인터넷에서 받으므로, 인터넷 되는 Wi-Fi 에서 한 번 열어 두면 된다 |
| 예전 화면이 보임 | **Ctrl + Shift + R** (강력 새로고침) |

쓰는 법 요약: **실시간**에서 ① ESP32 판정 ② 로봇 카메라 ③ 임무 단계를 보고, AI 판정으로 자동 출발시키려면 **제어 → 관리자 모드 → AI 자동 출발** 을 켠다. AI 가 안 되면 **제어 → 통으로 보내기** 버튼을 1초 누르고 있으면 그 통으로 간다. 오른쪽 아래 빨간 **정지** 는 어디서든 누를 수 있다 (웹 연결이 끊기면 로봇 본체 전원 스위치로).

## 실행 (명령어로)

```powershell
cd minhyeong/dashboard
python -m http.server 8765
```

| 주소 | 뜻 |
| --- | --- |
| `http://localhost:8765/` | 가짜 로봇으로 동작 (로봇 없이 화면 확인) |
| `http://localhost:8765/?robot=http://<로봇 IP>:8000` | 로봇 조종 서버에 연결 (실제 로봇 또는 `ROBOT_MODE=fake`) |

- 로봇 서버의 `CORS_ORIGINS` 에 **`http://localhost:8765`** 가 있어야 한다 (`jeongmin/robot/robot.env.example` 에 이미 들어 있음).
- 배포된(https) 사이트에서는 로봇 접속이 막히므로 시연 대시보드는 노트북에서 `http://localhost` 로 띄운다 (04-design 경계).
- 글꼴·아이콘·Tailwind 를 CDN 에서 받으므로 처음 열 때는 인터넷이 필요하다. 핫스팟에 인터넷이 없으면 화면 모양이 깨질 수 있다 → 시연 전에 확인.

## 화면 (DES-04)

분류·통 이름은 `can`(캔) / `pet`(페트) / `paper`(종이) — ADR-05. 마커 번호는 연결할 때 `GET /api/stations` 에서 받는다 (키트 블록 `stations.blocks.json` 도 그대로 맞음).

| 메뉴 | 기능 | 데이터 |
| --- | --- | --- |
| 실시간 | ① 로봇 카메라 영상 + 보이는 통 마커에 박스, 갱신 시각, 카메라 연결 상태 | `GET /api/stream`, `GET /api/mission` 의 `seen` |
| | ② **ESP32 판정 화면**: 위에서 본 트레이 그림 + 감지한 물체 박스, 종류별 확률 막대(확정 기준선), 확정 조건 3개(1등 80%·1·2등 차 20%·3번 연속), 보드 상태(빈 트레이 대기 → 인식 중 → 확정 → 비우기 기다림), 마지막 확정과 출발 여부·이유, 보드 USB 연결 | `GET /api/sort` 의 `last_verdict`(프레임·확정)·`last_decision`·`auto`·`board` |
| | ③ 로봇 상태 + 임무 단계: AI 판정 → 통 찾기 → 도착 → 쏟기 → 복귀 → 완료 | `GET /api/status`, `GET /api/mission` |
| 통계 | ④ 오늘 처리량, 임무 성공률, 평균 임무 시간, 평균 확신도, 통별·시간대별 개수, 탄소 절감량(출처 확인 전 "—") | `GET /api/history` 의 `items` 를 셈 |
| 기록 | ⑤ 임무별 결과(완료/실패/취소)·보낸 쪽(AI/웹)·걸린 시간·걸음 수·확신도, 통 앞 도착 사진, CSV 내보내기 | `GET /api/history`, 사진은 `GET /api/camera.jpg` |
| 알림 | ⑥ 연결 끊김, 장애물로 멈춤, 로봇 카메라 없음, 분류 보드 연결 문제, 임무 실패·취소, 통 가득 참 | 위 값의 변화 |
| 제어 | ⑦ 정지, 임무 취소, 통으로 보내기(1초 누르고 있기), 로봇 조종 화면 링크, 관리자(AI 자동 출발, 통 가득 참 기준, 통 비우기) | `POST /api/stop`, `/api/mission/cancel`, `/api/mission`, `/api/sort`, `/api/history/reset` |

임무 단계는 로봇 `phase` 를 이렇게 묶는다: `starting` → AI 판정, `search·align·approach`(목표가 통) → 통 찾기, `arrived` → 도착, `dumping·backing` → 쏟기, 목표가 `home` → 복귀, `done` → 완료. `failed`·`cancelled` 는 빨간/회색 줄로 이유(`message`)를 보여 준다.

기록·통 개수의 원본은 로봇 서버(`/api/history`)라서 새로고침해도 남는다. 도착 사진만 이 브라우저에 있다.

## 안전 (제어 화면)

- 웹에서 보내기 전 인터록: 로봇 서버 연결 · 임무 중 아님 · 앞 장애물 없음 · 통 여유. 로봇 서버가 다시 검사한다 (임무 중이면 409, 앞이 막히면 이동 거절).
- 통으로 보내기는 **1초 동안 누르고 있어야** 실행된다 (잘못 눌러 출발하는 것을 막음).
- AI 자동 출발 켜기·끄기, 통 비우기는 관리자 모드에서만.
- 웹 정지 = `POST /api/stop` (바퀴 정지 + 임무 취소). **웹 연결이 끊기면 정지 명령이 전달되지 않는다.** 이동 명령은 로봇이 3초 안에 스스로 멈추지만, 로봇이 스스로 하는 임무는 계속되므로 **로봇 본체 전원 스위치**로 끈다 → 시연 때 전원 스위치 담당을 정해 두자.

## 팀원과 맞춘 것 · 남은 것

- **이정민 (로봇)**: IF-04 기록 API 를 제안 형식대로 구현(PR #11) → 대시보드가 그대로 사용. CORS 예시에 `http://localhost:8765` 등록됨.
- **정유정 (AI)**: 판정 JSON `{"class","conf","ms"}`, 이름 `can / pet / paper / empty`. 바뀌면 알려 주기.
  - **지금 펌웨어(`xiao_sorter.ino`)와 맞춤**: 확정이면 `{"class":"can","conf":0.93,"ms":173,"n":1}`, 아니면 매 프레임 `{"class":null,"conf":0.00,"ms":173,"n":물체 수}`. 대시보드는 `class` 가 있는 줄만 확정으로 보고, `class:null` 줄로 "인식 중/대기"와 물체 수를 보여 준다.
  - **요청 (ESP32 판정 화면용)**: 확정 줄과 별도로 프레임마다(또는 0.5초마다) 한 줄을 더 보내 주면 트레이 그림·확률 막대·확정 조건이 움직인다. 보드는 사진을 보내지 않으므로 그림은 이 값으로 그린다.
    ```json
    {"event":"frame","probs":{"can":0.86,"pet":0.05,"paper":0.04,"empty":0.05},"box":[0.32,0.30,0.36,0.40],"streak":2,"state":"detecting","ms":173}
    {"event":"decision","class":"can","conf":0.93,"ms":173}
    {"event":"stuck"}
    ```
    `box` = FOMO 가 찾은 물체 위치 [x, y, 너비, 높이] (0~1, 96×96 기준), `state` = `ready` / `detecting` / `wait_empty`. 로봇 서버는 `event` 가 `decision` 이 아닌 줄을 출발에 쓰지 않으므로 지금 코드 그대로 받을 수 있다. 프레임 줄이 없으면 화면은 마지막 확정만 보여 준다.
- **이정민 (로봇) 요청**: 프레임 줄이 확정 판정을 0.2초 만에 `last_verdict` 에서 덮어쓰므로, `GET /api/sort` 에 마지막 확정만 따로 `last_decision` 으로 넣어 주기 (대시보드는 있으면 그것을 먼저 씀).
- **팀 결정이 필요한 것**
  - 통 "가득 참" 기준 개수 (지금 가정 10개, 관리자 화면에서 바꿀 수 있음, 이 브라우저에만 저장)
  - 탄소 절감 계수와 출처 (출처를 찾기 전에는 "— kg" 로 둔다)
