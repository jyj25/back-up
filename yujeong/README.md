# yujeong — AI (사진 수집 · Edge Impulse 학습 · ESP32S3 추론)

스마트 분리수거 로봇(AI2 8조)에서 **트레이 위 쓰레기가 무엇인지 알아보는 부분**을 맡는다.
XIAO ESP32S3 Sense 의 카메라로 찍은 사진을 보드 안의 모델이 바닥은 무시하고 **물체만 찾아** `can` / `pet` / `paper` / `general_trash`(그 외)로 구분하고(물체가 없으면 `empty`),
확정된 결과를 USB 시리얼로 라즈베리파이(로봇)에 JSON 한 줄로 보낸다. 로봇·웹은 다른 팀원이 맡는다 (루트 `README.md` 참고).

## 모델 결과

학습에 쓰지 않은 **테스트 세트**로 평가한 값만 적는다 (EI 의 "검증" 100% 는 거의 같은 사진이 섞여 있어 믿지 않는다).

| 시점 | 클래스 | 테스트 정확도 |
| --- | --- | --- |
| 첫 학습 (50회) | 5 (`general_trash` 포함) | 0/79 |
| 100회·드롭아웃 0.5 | 5 | 17/79 |
| 새 사진(멀리·위에서) 추가 | 5 | 49/94 |
| `general_trash` 제외 | 4 | 34/73 (paper 4/39, pet 30/30) |
| 캔 40장 추가 | 4 | 37/81 (can 8/12, paper 0/39, pet 29/30) |
| can 5장·paper 57장 추가 | 4 | 29/93 (can 11/13, paper 1/50, pet 17/30) |
| pet 11·empty 5·general_trash 13장 추가 (분류 모델 마지막) | 5 | 19/99 (can 11/13, empty 1/1, general_trash 0/3, paper 6/50, pet 1/32) |
| **물체 검출(FOMO 96×96, 60회)** | 4+빈 트레이 | 57/99 (can 10/13, pet 16/22, paper 29/50, general_trash 0/3, 빈 트레이 2/11) |
| 같은 설정으로 다시 학습 | 〃 | 49/99 (can 11/13, pet 6/22, paper 25/50, 빈 트레이 7/11) — 학습할 때마다 몇 장씩 흔들림 |
| PET 6장 추가·박스 보정 후 재학습 (최신) | 〃 | 51/100 (can 10/13, pet 13/23, paper 24/50, general_trash 0/3, 빈 트레이 4/11 — 7장에서 pet 오검출) |
| FOMO 160×160, 100회 | 〃 | 25/99 (물체를 거의 못 찾음) |
| **11/02 재학습**: PET 5장 + 실제 트레이 사진 56장(PET 27·종이 29) 추가 (FOMO 96×96, 60회) | 〃 | EI 테스트 117장: can 13/14, pet 19/30, paper 11/57 (35장 못 찾음·11장은 can 으로 읽음), general_trash 0/3, 빈 트레이 9/13 → 캔·페트·종이만 43/101 |

검출 모델의 정확도는 사진당 확신도(≥0.6)가 가장 높은 검출 하나로 판정한 값이다 (빈 트레이는 검출 없음이 정답). 

- 분류 설정: MobileNetV2 0.35 전이학습, 입력 96×96, 증강 all. 검출 설정: FOMO MobileNetV2 0.35, 입력 96×96, 학습률 0.001.
- 검출로 바꾼 까닭: 분류 모델이 물체 대신 장면(바닥·조명)을 외우는 것으로 보여, 바닥은 배경으로 두고 물체 위치만 학습시키려는 것이다 (효과는 위 표에서 19→49~57로 확인, 이유는 확정 아님).
- 검출 모델의 약점: 투명 PET 를 자주 놓치고, 빈 트레이에서 pet 을 잘못 검출하는 경우가 있으며(11장 중 4장), general_trash 는 학습 사진이 10장뿐이라 못 맞힌다.
- 최신 결과: 사진을 더해도 **정확도가 오르지 않고 클래스별로 크게 뒤바뀐다** (pet 29/30 → 17/30 → 1/32, 마지막은 pet 25장을 empty 로 읽음). paper 는 계속 거의 못 맞힌다.
- 이유로 짐작하는 것 (확인 안 함): 테스트 세트가 "클래스별로 가장 늦게 찍은 20%" 라서 촬영 장면이 학습 때와 다르고, 학습 사진은 장면(바닥·조명·거리)별로 뭉쳐 있어 모델이 물체 대신 장면을 외우는 것으로 보인다. 지금 방식으로 사진을 더하는 것만으로는 90% 에 가기 어렵다.
- 숫자가 오르내리는 이유: 서로 다른 물체가 클래스마다 수십 개뿐이고 테스트 세트도 작아서, 한 번 학습할 때마다 결과가 크게 흔들린다.
- 원인 (확인한 것): 데이터에 같은 사진이 많았고(can 207장 중 32장만 서로 다름), 물체 종류가 적다. 모델 구조 문제로는 보이지 않는다.
- `general_trash`(그 외 쓰레기)는 사진이 에어팟·안경집뿐이라 **빼기로 했다.** 사진은 EI 에 비활성화로 남겨 두었다 (`python ai/train_ei.py enable general_trash` 로 되돌림).
- 목표 정확도(90%), 추론 1초 이내는 요구값이다. 달성 여부는 아직 모른다.

## 지금 로봇이 쓰는 모델과 데이터 (2026-11-02)

- **Edge Impulse 데이터**: 전체 677장 (학습 518 + 테스트 159, 그중 42장은 비활성 → 쓰는 것은 학습 518 + 테스트 117). 학습 518장: paper 225, pet 187, can 70, 빈 트레이 21, general_trash 10, 한 사진에 여러 물체 5. 11/02 에 올린 61장은 PET·종이이고 박스를 달았으며(고정 위치), 사람이 EI 화면에서 확인했다. **캔 사진이 가장 적다.**
- **"검증 정확도"와 "테스트 정확도"는 다르다**: EI 학습 화면의 검증 정확도(float32 92.9%, int8 82.9%)는 학습 사진 안에서 떼어 낸 값이라 연속 촬영 사진이 섞여 부풀려진다. 처음 보는 물건에서의 정확도는 학습에 쓰지 않은 테스트 세트 값(위 표)이다. 문서에는 둘을 구분해서 적는다.
- **로봇이 실제로 쓰는 판정**: `JUDGE=pi` — XIAO(`xiao_stream` 펌웨어)가 사진만 보내고, 라즈베리파이가 `jeongmin/robot/model/jyj25.eim`(**float32** `.eim`, `ai/build_eim.py` 로 받음)으로 판정한다. 리눅스용 int8 은 이 프로젝트에서 출력이 비어 쓰지 못했다.
- **확정 모델 (11/02 저녁)**: 빈 트레이 50장·캔 80장(트레이 위, 2자세)·페트 5+27장·종이 29장을 더해 재학습한 float32 모델을 파이에 올려 쓴다. 파이에서 트레이 위 실제 물건을 20장씩 찍어 판정한 결과 **빈 트레이 20/20, 캔 20/20, 페트 20/20, 종이 20/20** (옛 모델: 빈 트레이 0/20 — 전부 캔, 캔 20/20, 페트 19/20, 종이 13/20). **같은 자리·같은 물건으로 잰 값이라 처음 보는 물건·다른 자세에서는 낮아질 수 있다** (위 테스트 세트 값과 다른 종류의 수치). 빈 트레이 기준 사진 비교(`PAPER_BY_TRAY_DIFF=1`)는 안전장치로 켜 둔다. 옛 모델은 파이의 `jyj25_prev.eim`.
- 개선 방향: 종이·캔 사진을 실제 트레이 환경에서 모양을 달리해 더 찍기(종이는 구긴 것·펼친 것·컵·박스 등), 재학습 → 파이 모델 교체 → 파이에서 비교 평가.

## 확정 로직 — 앞으로 이 방식으로 간다 (2026-11-02)

**물건 분류 (파이에서 판정)**
1. XIAO ESP32S3 는 USB 로 사진만 보낸다 (`xiao_stream`). 판정은 라즈베리파이가 Edge Impulse float32 `.eim` 으로 한다 (`JUDGE=pi`).
2. 모델은 11/02 저녁 재학습한 것(빈 트레이 50장·캔 80장·페트·종이 사진 추가)을 확정한다. 파이에서 트레이 위 실제 물건을 **20장씩** 찍어 판정한 결과:

| 실제 | 옛 모델 | 확정 모델 |
| --- | --- | --- |
| 빈 트레이 | 0/20 (전부 캔) | **20/20** |
| 캔 | 20/20 | **20/20** |
| 페트 | 19/20 | **20/20** |
| 종이 | 13/20 (7장 빈 트레이) | **20/20** |

   같은 자리·같은 물건으로 잰 값이라 처음 보는 물건이나 다른 자세에서는 낮아질 수 있다 (위 "테스트 세트" 수치와 종류가 다르다).
3. 안전장치로 **빈 트레이 기준 사진 비교**(`PAPER_BY_TRAY_DIFF=1`)를 켠다: 기준 사진과 같으면 빈 트레이, 다르고 모델이 아무것도 못 찾으면 종이.
4. 3프레임 연속 같은 종류일 때 확정, READY 버튼으로 출발.

**마커 찾기·쏟기 (회전 없이 앞뒤로만)**
1. 카메라는 오른쪽 마커 줄을 본다 (서보 15°, 몸은 돌리지 않는다).
2. 마커가 보이면 멈춰서 트레이 위 쓰레기와 같은 마커인지 판단한다. 다르면 그 옆을 지나가고, 다음 마커에서 다시 멈춰 판단한다.
3. 같으면 마커가 화면 가운데에 올 때까지 앞뒤로 맞춘 뒤(`pan_center: true`) 그 마커 옆에서 쏟는다. 다른 마커가 아직 옆에 있으면 다 지난 뒤에 쏟는다.
   - 카메라는 오른쪽을 보므로 **화면 왼쪽 = 진행방향 앞, 오른쪽 = 뒤**다. 마커가 왼쪽에 보이면 앞으로, 오른쪽이면 뒤로 가서 가운데에 맞춘다 (11/02 에 방향이 거꾸로였던 것을 고침).
   - **마커 줄과의 거리 유지**(`hold_row`): 가운데 근처 마커의 크기가 처음보다 25% 넘게 줄면 줄 쪽(오른쪽)으로, 커지면 반대로 0.12초 옆걸음한다. 방향 센서가 없어 로봇이 비스듬히 가는 것을 줄이려는 보정이며, 아직 실제 로봇으로 확인하지 못했다.
   - 쏟은 뒤에는 앞으로 간 시간만큼 후진해 출발선으로 돌아온다 (`return_to_start`). 다음 사이클은 로봇을 출발선에, 앞을 마커 줄과 나란히 놓고 시작한다.
4. 줄 끝이거나 앞이 막히면 후진하며 다시 훑는다. 쏟기는 1배→2배→4배 속도로 재시도한다.

코드는 `jeongmin/robot` (PR #6 으로 main 에 반영). 아직 실제 로봇으로 `pan_center` 쏟기 사이클을 끝까지 돌려 확인하지는 못했다.

## 구성

```
카메라 → 96×96 → EI 객체 검출 모델(FOMO, int8) → 물체별 위치·종류·확신도
      → 판정 로직 → JSON 한 줄 → USB → 라즈베리파이
(판정 로직 `sorter_logic.h` 는 아직 분류 기준(3번 연속·확신도 0.80·1·2등 차이 0.20)이며 검출 기준으로 고쳐야 한다)
```

판정 결과 형식 (팀 문서 IF-01, `docs/project/04-design.md`):

```
{"class":"can","conf":0.93,"ms":173}   확정
{"class":null,"conf":0.41,"ms":173}    판정 없음
{"error":"camera"}                     오류
```

## 사용법

**1. 사진 수집** — 보드에 `firmware/xiao_stream` 을 올리고 USB 연결 → `ai/collector/index.html` 을 Chrome/Edge 로 열기 → "보드 연결".
클래스마다 **서로 다른 물체를 여러 개**, 각도·거리·조명을 바꿔 가며 (연사 금지), 로봇 위 카메라와 같은 위치에서 찍는다.
파일 이름이 `클래스.시간.jpg` 라서 EI 가 라벨을 자동으로 읽는다.

**2. 학습** — `yujeong/.env` 에 `EI_API_KEY=...` 를 넣는다 (이 파일은 올리지 않는다).

```
python ai/train_ei.py upload <사진 폴더>     # 폴더 이름이 클래스 (can/empty/paper/pet), 가장 늦게 찍은 20% 는 테스트용
python ai/autolabel.py <사진폴더> --out boxes.json   # 물체 박스 자동 생성 (EI 화면에서 보정)
python ai/train_ei.py boxes boxes.json <사진폴더>    # 박스를 EI 에 올림
python ai/train_ei.py fomo 60 0.001 96       # 객체 검출 학습: 횟수 · 학습률 · 입력 크기
python ai/train_ei.py train 100 0.0005 0.5   # (예전) 분류 학습
python ai/train_ei.py eval                   # 테스트 세트 평가, 혼동행렬 출력
python ai/train_ei.py wasm                   # 브라우저 테스트 페이지용 모델 갱신
```

**3. 테스트** — `ai/tester/index.html` 을 열어 웹캠·보드·사진으로 분류해 보고, 실제 종류 버튼을 눌러 정확도를 쌓는다.
