## 3. P3 EI 업로드·학습 스크립트 (미구현, 요구만 확정)

| ID | 요구 | 정상 동작 | 오류 상황 → 처리 |
| --- | --- | --- | --- |
| T-01 | ZIP 을 읽어 클래스별로 정리 | 클래스 폴더·파일명 접두어에서 라벨 결정, 개수 출력 | ① 클래스당 50장 미만 → 경고 후 계속할지 사람이 선택 ② 폴더·파일명 규칙 위반 → 해당 파일 목록 출력 후 제외 ③ 손 포함 비율은 자동 판별 불가 → "수동 확인" 체크리스트를 출력 |
| T-02 | `.env` 의 `EI_API_KEY` 로 인증 | 프로젝트 이름·id 출력 (키는 출력 안 함) | ① 키 없음·형식 오류 → 안내 후 종료 ② 401/403 → "키 무효/권한 없음" 종료 ③ 네트워크 오류 → 3회 재시도 후 종료 |
| T-03 | 대상 프로젝트 확인 | 실행 전에 프로젝트 이름과 기존 샘플 수를 보여 줌 | **기존 샘플은 확인 없이 삭제하지 않음.** 기존 데이터가 있으면 새 프로젝트 사용을 권고 (A19) |
| T-04 | 업로드 + train/test 80/20 | 업로드 수·분할 결과 출력 | 일부 업로드 실패 → 실패 파일 목록 저장, 재실행 시 이어서 올림(중복 방지) |
| T-05 | Impulse 설정(96×96, 이미지 분류)·학습 시작 | 작업 진행률 출력, 완료까지 대기 | ① 제한 시간 초과 → 작업 id 를 알려 주고 종료 ② 학습 실패 → EI 로그를 출력하고 종료 코드≠0 |
| T-06 | 평가 결과 저장 | 정확도, 혼동 행렬, 추론 시간·RAM·Flash 추정(ESP32 타깃)을 `yujeong/ai/results/` 에 JSON 저장 | 정확도 90% 미달 → "미달"로 표시(자동 중단 없음, 다음 조치는 사람이 결정) |
| T-07 | Arduino 라이브러리 받기 | `.zip` 저장, 설치 안내 | 다운로드 실패 → 재시도 후 EI 웹에서 직접 받는 방법 안내 |

## 4. P4 추론 펌웨어 (미구현, 요구만 확정)

| ID | 요구 | 정상 동작 | 오류 상황 → 처리 |
| --- | --- | --- | --- |
| I-01 | 입력 받기 | 96×96 이미지를 받는다. **경로 미확정**(보드 카메라 / 웹캠→PC→보드) — A07 IF-02, 팀 결정 필요 | 입력 크기·형식이 다르면 → 오류 JSON 출력, 추론하지 않음 |
| I-02 | 분류 | 클래스와 확신도 출력: `{"class":"can","conf":0.93,"ms":173}` (LF 로 끝나는 한 줄) | 추론 실패 → `{"error":"inference","code":N}` |
| I-03 | 판정 확정 | 같은 클래스가 N회 연속이고 확신도 ≥ θ 일 때만 "확정" (기본 N=3, θ=0.8 — 가정) | 조건 미달 → `{"class":null,"conf":x}` ("판정 없음"), 서보는 움직이지 않음 |
| I-04 | 카메라 오류 | — | 프레임 획득 실패 → `{"error":"camera"}` 를 출력하고 재시도. 3회 연속이면 LED 로 알림 |
| I-05 | 성능 | 추론 1초 이내, 테스트 정확도·보드 실측 90% 이상 | 미달 → A11 에 FAIL 로 기록하고 재학습(REQ-05) |
| I-06 | 출력 전달 | 서보 제어·UNO·웹이 같은 JSON 을 쓴다 (A07 IF-02) | 받는 쪽이 파싱 실패하면 그 줄을 버리고 다음 줄을 기다림 (받는 쪽 요구 — 로봇·웹 담당과 합의) |
| I-07 | 재학습 | 오분류 사진을 모아 최소 1회 재학습, v1/v2 비교 기록 | — |

## 5. 공통 (비기능)
- 비밀값(`EI_API_KEY`, Wi-Fi 정보)은 저장소·로그·화면에 출력하지 않는다. `.gitignore` 로 제외한다.
- 사진 원본은 공개 저장소에 올리지 않는다 (손·얼굴 포함 가능).
- 오류 문구는 "무엇이 안 됐고 다음에 무엇을 확인할지"를 한 문장으로 쓴다.
