## 1. 전체 흐름

```
카메라 프레임 → 전처리(중앙 정사각형 크롭 → 96×96) → EI 모델(int8) → 클래스별 확신도
   → 판정 로직(sorter_logic.h) → JSON 한 줄을 USB 시리얼로 출력 → 라즈봇이 읽음(pi_reader.py)
```

| 단계 | 담당 파일 | 상태 |
|---|---|---|
| 모델 → 코드 | EI 에서 내려받은 Arduino 라이브러리(`run_classifier`) | 아직 안 내려받음 |
| 추론 펌웨어 | `firmware/xiao_sorter/xiao_sorter.ino` (예정) | **미작성** |
| 판정 | `firmware/xiao_sorter/sorter_logic.h` | 작성, 보드 시험 PASS |
| 수신 | `firmware/xiao_sorter/pi_reader.py` | 작성, 줄 파싱만 확인 |

## 2. 전처리 (학습과 반드시 같아야 함)

- 수집기는 사진을 **중앙 정사각형으로 잘라 96×96 으로 줄여** 저장한다. 추론도 같은 순서를 쓴다: 카메라 VGA(640×480) → 중앙 480×480 크롭 → 96×96 축소.
- EI 임펄스는 96×96, `squash`, RGB 이다. 이미 정사각형이므로 squash 와 크롭 결과가 같다.
- 카메라 JPEG 를 RGB 로 풀어서 쓴다(`fmt2rgb888` 또는 `jpg2rgb565`). 풀기에 실패하면 그 프레임을 버린다.
- 알려진 문제: 카메라 영상이 90° 돌아가 있다. 수집과 추론이 **같은 방향**이면 되므로 수집 때 돌렸다면 추론도 똑같이 돌려야 한다. 아직 어느 쪽으로도 보정하지 않았다.
- 틀리면 생기는 일: 학습과 다른 전처리를 쓰면 확신도가 무의미해진다. 시험 항목에 "수집 사진 한 장을 보드에 넣어 EI 웹 결과와 비교"를 넣는다.

## 3. 모델 실행

- EI 에서 내려받은 라이브러리의 `run_classifier()` 를 쓴다. 입력은 `signal_t`(픽셀 값 공급 함수), 출력은 `result.classification[i].value`(클래스별 확신도).
- 모델은 **int8 양자화**(EI 권장)를 쓴다. 메모리는 PSRAM(8MB, OPI)에 둔다. 빌드 옵션 `PSRAM=opi`.
- 클래스 순서는 EI 가 알파벳순으로 정한다: **can(0), empty(1), general_trash(2), paper(3), pet(4)**. 순서는 라이브러리의 `ei_classifier_inferencing_categories[]` 로 확인해서 코드에 하드코딩하지 않는다.
- 속도: 보드 실측 전이라 알 수 없다. 요구는 1초 이내(I-05)이고, 실측 값은 A09-A11 에 적는다.

## 4. 판정 로직 (`sorter_logic.h`)

한 프레임의 결과로 바로 서보를 움직이지 않는다. 헛판정을 줄이기 위해 아래 조건을 모두 만족할 때만 **DECISION** 을 낸다.

| 조건 | 기본값 | 근거 |
|---|---|---|
| 1등 확신도 | ≥ 0.80 | 가정 |
| 1등과 2등 차이 | ≥ 0.20 | 가정(애매하면 거절) |
| 같은 결과 연속 | 3회 | 가정 |
| 결과가 `empty` 아님 | — | 빈 트레이는 판정 대상 아님 |

- 판정 후에는 `empty` 가 확신도 ≥ 0.70 으로 3번 연속 나올 때까지 새 판정을 내지 않는다(같은 물건 중복 방지).
- 판정 후 10초 안에 안 비면 **STUCK**(물건이 안 떨어짐).
- 이 기준값은 모두 가정이다. 쓸만한 모델이 나온 뒤 실제 확신도 분포를 보고 정한다.
- **고쳐야 할 것:** `Config` 가 4클래스(`num_classes=4`, `empty_idx=1`) 기준이다. `general_trash` 가 추가되어 5클래스가 되면 `num_classes=5` 로 바꾼다. `empty_idx=1` 은 그대로이고 paper·pet 번호가 밀린다.
- **`general_trash`(그 외 쓰레기) 처리:** 모델이 `general_trash` 를 1등으로 내면 DECISION 의 클래스가 `general_trash` 이다. 이 클래스를 서보가 어느 통으로 보낼지는 로봇 담당과 정해야 한다(미결정, A08).
  모델이 확신하지 못해 DECISION 이 안 나올 때를 `general_trash` 로 볼지는 **정하지 않았다.** 이렇게 하면 헛판정이 모두 일반쓰레기로 가므로 정확도 확인 뒤 결정한다.

## 5. 출력 형식 (IF-02, 제안 — 합의 전)

한 줄에 JSON 하나, 줄 끝은 LF.

```
{"class":"can","conf":0.93,"ms":173}   판정 확정
{"class":null,"conf":0.55,"ms":170}    판정 없음
{"error":"camera"}                     카메라 프레임 실패
{"error":"inference","code":-5}        추론 실패
```

- 받는 쪽은 `{` 로 시작하지 않는 줄(부팅 로그 등)을 버린다. `pi_reader.py` 가 이렇게 한다.
- 라즈봇은 USB 시리얼(예: `/dev/ttyACM0`)로 읽는다. 노트북 수집기(Web Serial)와 **동시에 못 쓴다.**

## 6. 오류 처리

| 상황 | 동작 |
|---|---|
| 카메라 프레임 실패 | `{"error":"camera"}` 출력 후 재시도, 3회 연속이면 LED 알림 |
| 크기·형식 오류 | 오류 JSON 출력, 추론하지 않음 |
| `run_classifier` 실패 | `{"error":"inference","code":N}` 출력, 다음 프레임에서 재시도 |
| 확신도·격차 미달 | `{"class":null,...}` 출력, 서보 동작 없음 |
| STUCK | 이벤트로 알림. 재시도·알림은 호출하는 쪽이 결정 |
| 라즈봇이 줄을 못 읽음 | 그 줄을 버리고 다음 줄 대기. 10초 무응답이면 경고(`pi_reader.py`) |
