# 구조·경계·배치 설명

문서 ID: A06 / 버전: 0.1 초안 (2026-10-30)
근거: README 구성도, Xiao.md

## 시스템 경계
- 포함: 카메라, XIAO ESP32S3(AI 추론·서보·Wi-Fi), 아두이노 UNO 패널, 서버, 웹 대시보드, 휴대폰 웹앱, (선택) 라즈봇
- 제외: 실제 재활용 시설, 클라우드 학습 외의 외부 서비스

## 데이터 흐름 (README 구성도 기준)
```
카메라 ─ 96×96 사진 ─▶ XIAO ESP32S3 ─ AI 판정(class, conf) ─▶ 서보: 트레이 기울이기 ─▶ 통
                          │
                          ├─▶ UNO: 통별 개수(FND), 상태색(RGB LED), IR 리모컨 수동 조작
                          └─▶ 서버 ─▶ 웹 대시보드 / 휴대폰 웹앱 ─(통 가득 참)─▶ 라즈봇(선택)
```
- 입력: 사진 → 처리: 보드 안 AI 추론(엣지, 인터넷 불필요) → 출력: 서보 각도, 패널 표시, 서버 기록
- **카메라는 두 가지 경로 후보**: ① 노트북 웹캠 → 대시보드 → 사진을 보드로 전송 (README) ② 보드 자체 카메라 (이 보드에서는 OV3660 초기화·영상 확인됨, README 는 고장이라 적음). 결정은 A08 ADR-01.

- **라즈봇과 USB 연결(나중에):** ESP32 의 판정 JSON 을 라즈봇이 USB 시리얼로 읽는다. 이 경우 서버 전송을 라즈봇이 대신할 수 있다 (가정, ADR-02·A07 참고).

| 모듈 | 위치(예정 폴더) | 책임 |
| --- | --- | --- |
| 수집·학습 | `yujeong/ai/` | 사진 수집기, Edge Impulse 학습 스크립트 |

## 배치·저장
- 추론은 보드, 기록은 서버 DB(또는 Supabase), 학습 사진은 각자 PC → Edge Impulse.
- 사진 원본은 공개 저장소에 올리지 않는다.

## 관심사별 질문
| 누가 | 무엇이 궁금한가 | 어디서 보나 |
| --- | --- | --- |
| 발표 청중 | 왜·어떻게 동작하나 | 이 문서의 흐름도 |
| 로봇 담당 | 서보를 누가 제어하나, 핀 충돌은 | A20, ADR-03 |
| 웹 담당 | 보드가 무엇을 보내나 | A07 |
| AI 담당 | 입력 사진은 어디서 오나 | ADR-01 |

## 대안·제약
- 학습 모델은 보드 메모리(8MB PSRAM)와 1초 제한 안에서 고른다.
- 서보 힘이 약하므로 빈 용기·작은 물건으로 시연한다.
- 미해결 항목은 A08.
